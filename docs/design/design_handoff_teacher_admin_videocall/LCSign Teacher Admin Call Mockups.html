TTeacher dashboard: a home page, a roster built for 40 students, one place for what the class learns
The shell changes once for every section. The rail holds the class switcher, four sections and the class code. The class header with its stats no longer repeats above every section: the stats live on Today only, so each section's real content starts at the top. Sections: Today (new, T1 proposal), Students (roster + student detail), What they learn (plan and modules in one place, as two steps), Progress.
T1Today (home) · desktop 1440×900 · uses only data that exists today
Why: problem 2 ("nothing says what needs me today"). Every row is a query over data the dashboard already loads.
  1. Needs you is one sheer GlassCard with a list of rows, sorted by urgency: missed calls (newest first), students under 25%, signs the class is stuck on (the existing “to review” query), modules due in the next 7 days or overdue, students with no class. Each row has one action. A row disappears when it's handled. With none, the card shows the all-caught-up state (T9).
  2. The class average uses ProgressBar and the same computeOverall value students see. It's shown here only, not repeated on every section.
  3. Online now is the only place outside the roster with Call buttons, so they don't turn into a column of 40. "On a call" students show "Busy" instead of a button.
  4. The rail badge "5" counts the Needs-you rows (gold, attention token). It's text in a pill, with an accessibility label "5 things need you".
  5. The class code moved to the rail foot, visible from every section: Copy is one tap. New code and print are on the Students page (T2).
T2Students · roster table for 40, row menu open · desktop 1440×900
Why: problem 3 (the roster doesn't scale), proposal T3. 40 rows at 52px is a table you scroll, not a wall of cards.
  1. Filter chips are a SegmentedToggle (size md) with live counts. "Online" filters on presence. "Under 25%" uses the same overall value as Today. "Not started" means overall 0%.
  2. Sortable columns: Name, Status, Overall (default, ascending), each group. The sort header is a Pressable with accessibilityRole="button" and a sort-state label ("Overall, sorted lowest first"). Unavailable groups have no column; they're named once in the toolbar as "soon". The per-group figures are learned/available, using the class plan for words.
  3. Call is a filled button only when the student is Online. When they're Offline or On a call it's a dimmed icon button that still works for Offline (the call rings out and becomes their missed call) and is disabled for On a call. This removes the column of 40 identical violet buttons.
  4. Remove moved off the row into the ⋯ menu, with "Remove from class…" leading to ConfirmInline under the row (wording unchanged). Call and Remove are no longer side by side. The menu is an RN Modal anchored popover, raised material, 44px items.
  5. Invite students opens the existing InviteStudents list in a sheet. The "Print class code" button opens a print page with the code in big type (feasible today with window.print). A QR code on that page is a PROPOSAL: it needs a QR library.
Tapping a row (not just ⋯) opens the student detail drawer (T3). At 7 students the table works unchanged and just ends early.
T3Student detail drawer (proposal T2, all data exists) · desktop 1440×900
Why: problem 3 (no student detail), proposal T2. Everything shown comes from Appendix A: progress rows, modules, saved call notes.
  1. A right-side drawer, 600 wide, over an overlay scrim. It's an RN Modal with transparent and animationType="slide", or none with reduced motion. It uses opaque sheer glass, not frosted, because it shows gold stars and green marks, which theme.ts forbids on frosted glass.
  2. The tiles reuse the student dashboard's tile component at 52×60 (a teacher size, read-only). Tile states: learned = check badge + green ring. Tried = gold ring + stars. Not yet = flat well + "not yet". Stars are 0–3 in quarter steps, and the state is never shown by colour alone.
  3. Module rows use ProgressBar (sm). Call notes are the saved notes for this student only. The caption says that unsaved calls don't appear, so there's no implied call history.
  4. Primary: Call Ana (only filled when online, as in T2). ⋯ holds Remove from class. Esc / close returns focus to the row that opened it.
T4What they learn · step 1, words in the plan, unsaved changes · desktop 1440×900
Why: problem 4 (plan vs modules is confusing), proposal T4. One section, two numbered steps, with one sentence above them that says how they differ.

  2. The editor body is the existing ClassPlanEditor, restyled: the language toggle with a "•" when that language has unsaved edits (existing behaviour), a summary bar, search, Starter / Pick all / Clear all, and tri-state category rows with 52px hit targets. T5What they learn · step 2, modules list · desktop 1440×900
  1. Reorder keeps today's up/down buttons (44px, disabled at the ends) with a visible position number. Drag-to-reorder isn't proposed, because it's hard to make accessible in RN.

T6Module editor drawer with the date picker open · desktop 1440×900

T8Progress · class at a glance: per-sign completion + student × sign grid · desktop 1440×900
Why: problem 5 and proposal T5. The class is shown as one picture, and every mark is readable without colour.
  1. A per-sign column chart shows the share of the class that learned each letter. Columns under 30% turn gold and are listed in "Letters to review", so colour is never the only cue. Built from react-native-svg rects.
  2. The student × sign grid uses three shapes: a filled square with a check (learned), a ring with a dot (tried, not learned), and an empty well (not tried). Cells are 20px on a 23px pitch. Each row is one View with accessibilityLabel "Gina Ramos: learned 4 of 26 letters. Tried, not learned: E, F, G". The grid as a whole is skipped by screen readers in favour of these row labels. Words (80+) scroll horizontally in category blocks with a sticky name column.
  3. "To review" no longer reuses the progress bar for a different meaning. It's a 3-part stacked strip (learned / still learning, striped / not tried) with the counts in words. "⋯" offers Make a module from these and Practise in a call (which opens the roster filtered to online students).
  4. Per-group completion uses ProgressBar. Clicking a student name opens the student detail drawer (T3). "Sort by Overall" puts the lowest first, as today.

SToken additions and component states used above
Every new token is an alias or a darker step of an existing hue, named by its role. No new palette, no new fonts. Values and reasons are in README.md → Token additions.
S1New semantic tokens
S2States: rest · pressed · selected · disabled · focus · loading (buttons, call toggles, presence, quality)
Pressed = inset + scale 0.97 (the material pass's raised→inset rule). Focus = 2px focusRing (gold) outline, offset 2, on every Pressable on web. Disabled = 45% opacity and a reason in text nearby or in the accessibility hint. Loading keeps the button's width and swaps the icon for a static-able arc.
